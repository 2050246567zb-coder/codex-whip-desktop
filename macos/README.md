# Codex Whip 产品版 2.2.92 for macOS

## 用户自动安装

先阅读 [完整安装说明](https://2050246567zb-coder.github.io/codex-whip-desktop/INSTALL.md)。把 [扫码安装页面](https://2050246567zb-coder.github.io/codex-whip-desktop/) 的提示词发给当前 Mac 上的 Codex，它可以使用自动安装脚本完成下载、校验、复制到固定应用目录、启动和打开授权设置；用户不再需要手动从 DMG 拖动应用。不要从 DMG 直接运行后就判断安装完成。系统辅助功能、蓝牙及安全确认仍需用户亲自处理。

## 2.2.92 鼠标滚动、连接状态和授权引导

修正 Mac 鼠标滚轮一次滚动就跳到设置页顶部或底部的问题；普通滚轮逐步滚动，触控板保留连续滚动。发现或失去 Codex 窗口时，设置页的连接状态自动同步；输入框暂未就绪不会把已找到的窗口显示成未连接。缺少设备控制权限时只显示一份软件引导并打开相应设置页面，不再同时要求系统弹出另一份辅助功能授权窗口。授权仍需用户亲自完成；更换安装包后，旧签名条目可能需要重新添加。

## 2.2.91 权限、语音发送与设置滚动

同一用户配置只允许一个 Mac 图形界面进程；从桌面、DMG 或应用目录重复打开时激活已经运行的应用。权限引导显示实际运行的应用路径，不再固定指向另一份 `/Applications` 副本；权限设置打开失败不会反复触发系统请求，已确认授予的权限在本次运行中不会因短暂状态波动重新弹窗。这不能代替用户首次授权，也不能让旧版本的签名授权自动适用于新的未签名身份。

语音发送先激活 Codex，再等待其无障碍树就绪，按 Electron 的公开接口请求暴露网页界面。输入框定位兼容较窄分栏与较小高度，跳过搜索框和窗口之外的控件；遍历减少聊天静态文本子节点并提高节点上限，截断或输入框不唯一时仍拒绝输入。失败日志仅记录角色、边界、淘汰计数和 AX 错误码，不记录草稿、会话正文或识别文字。初次发送检查失败仍保留发送开关。

设置页在所有内容控件上统一处理滚轮及 Tk 9 的 `TouchpadScroll`，不再要求鼠标停在右侧滚动条。长文字编辑器优先内部滚动，抵达边界后继续滚动设置页；新增消息行自动继承此行为。

## 2.2.90 Mac 端引导演示

功能演示开头增加静止归中提示：手柄头部对准屏幕方向并静止三秒，手柄会自动居中。引导现在为九步。时钟演示固定展示表盘，不再受引导窗口中的鼠标移动影响而反复退出、重入，避免鞭绳指针扭曲。

## 2.2.89 Mac 端语音打包与首次引导修复

Mac 安装包现在附带独立的 HTTPS 根证书和已校验 SHA-256 的完整 `ggml-small-q5_1.bin` 本地识别模型。豆包连接明确使用包内 CA，不再依赖打包机器的 Homebrew OpenSSL 证书路径；云端暂时不可用时，Whisper 可以直接使用包内模型，无需在用户电脑上下载。构建缺少任一资源时会失败，避免发布不完整安装包。约 190 MB 的模型会增加安装包大小。

首次启动依据 `interface-preferences.json` 中实际保存的引导状态判断，而不再依据用户数据目录是否已有日志或出厂设置。新用户连接并移动手柄后进入功能演示及方向校准；老用户已完成的引导和个人校准仍保留。

## 2.2.88 Mac 新用户默认设置与应用图标

首次启动只导入经过校验的八种设置：本机已调好的挥鞭阈值和灵敏度、双敲模板与语音设置、方向校准、省电模式、音效和伤口频率，以及一条预设发送文字。发送开关沿用本机当前的开启状态作为产品默认值；全新用户仍从入门引导开始。“恢复默认”只替换这些设置，并把发送开关设为开启；保留蓝牙设备身份、窗口位置、引导完成状态、录音、识别日志和传感器偏置。Mac 应用图标使用 Windows 2.2.85 正式发布版的鞭子 logo，转换为 macOS `.icns`。

## 2.2.87 Mac 端输入状态修复

模拟 ⌘V 和光标跳转时显式发送 Command 按下与松开事件，修正此前缺少松开事件的输入序列，以解决后续手动输入偶尔显示为斜体的问题。临时粘贴完成后按实际剪贴板变更计数恢复原内容；若期间用户复制了新内容，仍保留用户的新内容。语音发送继续使用已验证的定向 Return。

## 2.2.86 Mac 端录音静音判断

Mac 端旧设置中的 1.2 秒默认静音时间会自动升级为 2.2 秒；之后在开发者录音参数里手动设置较短时间仍会生效。固件 `0.8.6` 要求连续语音帧才进入或延长说话状态，轻声续说使用较低阈值，噪声基线缓慢跟随环境变化；单次噪声尖峰不会延长录音。静音和最长录音时间按实际采集的 PCM 时长计算，避免蓝牙传输排队导致提前结束。

## 2.2.85 Mac 端语音发送与充电识别

手柄识别的文字会先追加到 Codex 已有草稿末尾，再通过一次定向 Return 发送给 Codex 进程。输入前真实点击消息框以建立焦点，临时粘贴后恢复原剪贴板；若用户期间复制了新内容，则保留用户的新内容。识别结果在一次挥鞭后即从待发送队列移除，避免倒计时内重复输入；发送异常不会关闭设置中的发送开关。运行日志只记录录音、挥鞭与发送阶段，不保存语音内容或识别文字。

固件 `0.8.5` 同时上报充电芯片状态与 USB 外部供电状态。连接 Mac、充电器或移动电源时，界面可区分“正在充电”和“已接电源”；电池已满而停止充电时仍会显示外部供电。

## 2.2.77 回退原生听写并保留录音修复

Mac 端恢复 2.2.75 的语音输入：手柄录音由豆包 API 或本地 Whisper 识别，不显示原生听写开关，也不需要 BlackHole。固件 0.8.4 在蓝牙连接仍处于省电速度时等待恢复活跃连接，避免开始录音后因传输阻塞而丢失音频；桌面端增加语音、发送与武装失败的运行日志，便于排查真实错误。

## 2.2.75 Codex 文字输入修复

发送识别文字时通过 macOS 无障碍文本接口写入 Codex 输入框，追加时保留已有草稿；输入内容未经核对不会提交，也不再用模拟键盘输入整段文字。

## 2.2.74 蓝牙连接诊断

系统蓝牙关闭或拒绝应用访问时，主页明确提示原因；蓝牙恢复后继续自动重连。连接失败原因也记录到本地运行日志，便于排查。

macOS 与 Windows 共用动作识别、校准、设置、界面动画、鞭绳物理、伤口、消息和
语音状态机；窗口控制使用 macOS Accessibility/AppKit/Quartz，BLE 使用
CoreBluetooth。平台实现可以不同，但用户可见功能与配置格式保持一致。

## 构建（Apple Silicon）

```bash
brew install python@3.12 python-tk@3.12 cmake
export CODEX_WHIP_PYTHON="$(brew --prefix python@3.12)/bin/python3.12"
bash macos/build-macos.sh
```

产物在 `macos/dist/`。官方 GitHub Actions 构建会按项目所有者的选择从仓库 Secret 注入豆包 API Key，公开安装包中的 Key 可被提取；自行构建时未传入 Key 的包仍可让用户在本机配置。打包脚本在没有显式传入 Key 却发现源码目录残留私有 Key 文件时会拒绝构建，避免误用旧 Key。未配置开发者证书时是 ad-hoc 签名测试包；它通过结构和
签名自检，不等于已公证发行。

首次使用需在“系统设置 > 隐私与安全性”授予蓝牙和设备控制权限（旧版系统称辅助功能）。该权限
用于查找唯一的 Codex 窗口、附着鞭子层和发送已确认的文字。

首次启动会导入公开的出厂设置，已有的个人设置文件不会被覆盖。出厂设置不包含
API Key、本地文件路径、录音、识别日志、蓝牙设备身份、窗口位置、引导完成状态或单块开发板专属的陀螺仪零偏。

## 语音输入

双敲后开始录音，软件优先使用已配置的语音 API，否则使用本地 Whisper。
识别文字保留到下一次挥鞭发送。产品界面不再包含 BlackHole 或 Codex 原生听写入口。

从源码运行时，先执行 `bash macos/prepare-speech.sh` 准备 Mac 原生 Whisper（需 CMake 和 Xcode Command Line Tools）。完整打包脚本也会自动执行此步骤。正式 Mac 安装包已带有本地识别模型，首次启用时无需联网下载。仅从源码直接运行、且没有模型文件时，程序才会下载并校验模型。构建时可设置 `CODEX_WHIP_WHISPER_MODEL_SOURCE` 为已有模型的路径；否则构建机从官方模型仓库下载。两种方式都会校验文件大小和 SHA-256。

## 验证

```bash
bash macos/verify-macos.sh
```

GitHub Actions 可验证 Apple Silicon 构建、单元测试和合成 UI 冒烟；真实蓝牙、
BLE、当前 Codex AX 元素、屏幕叠层和语音识别仍须在目标 Mac 按
`MACOS_ACCEPTANCE.md` 实测。

## 2.2.73 语音发送修复

语音识别结果会接在 Codex 输入框现有草稿末尾，并在核对完整内容后一起发送。
普通预设消息仍会拒绝覆盖草稿；发送提醒与日志会说明这两种行为。

## 2.2.72 引导和发送修复

Codex 输入框保留草稿时可开启发送开关；实际发送仍会保护现有草稿，清空后才能提交新文字。
功能演示第六步展示循环的 10 秒倒计时、文字消逝效果和底部说明。
引导及校准按钮改为圆角黑边、黑色文字；两个方向的校准演示使用鞭绳物理模拟。

## 2.2.71 前台应用适配

Codex 或 Codex Whip 处于前台时，Codex 叠层保持可见，主页保留鞭子形态；
切换到其他应用时才隐藏叠层并显示问号。设置窗口仍按既有行为隐藏叠层。

## 2.2.69 界面适配

Codex 不在前台时，Codex 叠层隐藏，主页鞭子切换为问号；返回 Codex 后恢复。
设置窗口打开时隐藏主页。macOS 按钮不再显示多余焦点边框；消息卡片拖动时
仅高亮拖动手柄。删除、消息顺序和添加图标使用随按钮等比缩放的高清图片。

## 2.2.70 修复

三个消息图标改为固定尺寸。修复前台状态检查的初始化错误，以免主页刷新停止在
Connecting 动画。启动时静默检查辅助功能和蓝牙授权；缺少授权时仅打开对应系统
设置一次，并显示操作引导，不会自动更改系统权限。

本地主页动画流畅度可用 `python macos/benchmark-animation.py --output macos/dist/animation-report.json`
复测；它使用合成姿态数据，不连接手柄或 Codex 叠层。

## 2.2.64 同步说明

保留 AppKit 透明叠层、右键/Control-click 表盘、主页状态动画和 Mac 原生 Whisper。
CoreBluetooth 设备标识（UUID）用于记忆手柄；按广播信号强度选择附近设备。
共享固件 0.8.1 使用二进制音频、CRC16 和分片确认；桌面仍兼容旧 AUD1 固件。
源码升级不会自动刷写手柄；已安装最新固件的手柄无需重复刷写。
出厂校准 JSON 按仓库 LF 换行校验；已有本机校准不被覆盖。

2.2.64 将双敲门槛限制为 0.5–4.0 g，默认 1.0 g。语音设置升级到 schema 2；旧版语音设置会恢复默认（包括关闭语音开关），升级后请重新开启并检查灵敏度。保留 BLE 录音开始、结束和断线诊断日志。

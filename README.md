# Codex 鞭子

挥动握柄后，由 XIAO nRF52840 Sense 在本地识别动作，通过 BLE 向 Windows/macOS
发送挥动数据；电脑端去重、选择文案，再把文案提交到当前打开的
Codex 桌面窗口。

## 当前实现

- 产品版 `2.2.51` 的 Windows 与 macOS 共享同一套功能和配置格式；窗口、蓝牙与
  音频设备控制分别使用各平台的原生适配层。设置 > 输入 > 语音输入提供互斥的
  “文字识别”和“Codex 原生听写”：前者保留本地/云端转写，后者把手柄音频送入
  已知虚拟音频设备并启停 Codex 自带听写，下一鞭只提交已有草稿。Windows 支持
  Virtual Audio Driver/VB-CABLE，macOS 支持 BlackHole 2ch；未找到已知设备时
  会拒绝启动，不会把录音回退到扬声器。

- 固件 `0.7.0` 通过 XIAO nRF52840 Sense 板载电池分压电路读取锂电池，
  每 30 秒通过 BLE 上报百分比与充电状态。产品版主界面左上角使用经典胶囊电池：
  普通状态为黑色百分比，低于 20% 变红，充电时变绿并显示闪电；悬停只显示
  剩余百分比，不显示电压。断开手柄后立即清除旧读数。

- 双敲运行识别和“一次双敲自动设置”共享 `0.75 g` 的物理冲击下限，普通移动
  不会被录入为敲击，旧的过低设置也会受到运行时保护。XIAO 进入省电状态后，
  主页和目标窗口上的鞭子会平滑变为呼吸浮动的 `Z`，标题在 `deep sleep.` 到
  `deep sleep...` 之间循环；唤醒时从当前帧非线性变回实体鞭子。

- 桌面 `2.1.7` 修正手持静止 3 秒自动归中的跟随和绳索回归问题。允许过滤后角速度 ≤12°/s、
  加速度模长偏离 1g 不超过 0.20g，且这段时间相对起始朝向偏转不超过 3°；
  轻微手抖不打断计时，持续慢转仍通过累计偏转识别为运动。使用连续传感器时间，
  超过 120ms 的样本中断会清空计时，不把断连时间算成静止。
  自动归中只减去显示角度偏移，不再重建手动校准的姿态基准、方向轴或改变后续映射。
  屏幕回中以整体平移/旋转绳索当前和上一帧坐标的方式进行，不额外注入甩绳速度；
  重力、原有绳速和阻尼继续计算，不冻结物理。安装/动作学习档案、挥鞭阈值和零偏不变。
  方向校准向导期间暂停，鼠标持鞭不被抢走。真正的挥鞭识别仍接收原始六轴数据，
  不接收显示归中位移；本次轻微运动实测未复现板端 WHIP 误触发。
- 桌面 `2.1.5` 修复首次方向校准的交互与判定：取消 15 秒采集时限，
  点击起点、开始、录入和归中时不再强制静止。每步有独立起点，允许自然混合轴
  转腕及动作修正；“向右”的正负号从用户示范中学习，不再预设必须为正。
  数据不足可以继续转动后再次录入；断流仅要求重录当前动作，已完成步骤保留。
  最后必须归中试方向并明确确认，才保存独立的 `mounting-profile.json`。
  本机保留最近一次录入/失败的六轴诊断（最多 6000 帧），不含声音、对话或截图。
- 桌面 `2.1.1` 修复鼠标抽打只有握柄移动的问题：从实时绳形起势、甩绳、
  鞭梢精确命中点击点、回弹后交回物理模拟。重力为 `2.1.0` 的约 3.3 倍，
  惯性保留系数从 `0.84` 降到 `0.80`；固定 60 Hz 物理步长消除帧间隔改变造成的漂浮感。
  姿态映射改用连续四元数旋转向量，移除 90° 轴投影奇点和 180° 跨边翻转。
- 桌面 `2.1.1` / 固件 `0.6.0` 继续使用现有 XIAO nRF52840 Sense，分别处理
  姿态跟随、动作过程识别和绳索物理；不再把线性加速度累加成屏幕位移。
  实体传感器的水平、垂直全量程映射到 Codex 窗口正中央的
  `1/3 宽 × 1/3 高` 区域；手柄会在这个区域内跟随，但不会越过四条边界。
  鼠标拖动及鼠标抽打的精确落点不受影响。

- XIAO nRF52840 Sense：LSM6DS3TR-C，`±16g`、`±2000 dps`、416 Hz。
- 板端状态机保留运行时阈值和用户已学习的参数。`0.6.0` 增加“转腕主导”分支：
  持续转动、足够角位移、主轴集中度、动作时长和最终制动/静止过程共同判断；
  转腕分支不再强制要求大的线性加速度、净方向一致性或加速度峰值同步，
  以兼容制动回弹。持续摇晃超时仍拒绝，单次加速度冲击不等于挥鞭。
- 固件 `0.6.0` 使用 RAW5 六轴流：角速度分辨率从 `16 dps` 提高到 `0.1 dps`，
  加速度分辨率从 `0.125 g` 提高到 `0.001 g`，每帧携带实际采样时间。
  按真实时间约每 10 ms 发送一个样本，不再假设每次轮询都能读到新数据。
  这是传输分辨率改善，不代表传感器本体精度提高。保留按需开启的 16 kHz PDM 录音与 IMA ADPCM BLE 传输。
  语音模块默认关闭；录音期间暂停六轴流和挥鞭事件，结束后恢复。
  完成录入后由电脑端 V3 轨迹分段和 DTW 模板匹配接管。
- 桌面 `1.3.5` 在 Whisper 前增加 Silero VAD 人声分段和非语音标记抑制；未检测到
  可用人声时保持空白且不会发送。只过滤完整命中的常见静音幻觉，正常命令里的
  “关注”等词不会被误删。已有语音候选时再次双敲，会在新录音确认开始后清除旧候选并重新识别。
- Windows 接收端：Bleak 自动扫描、连接、断线重连和分包重组。
- 第二层保护：序号去重及1.5秒最短发送间隔。
- Windows 图形界面：双击运行、自动监听，显示蓝牙/Codex/发送状态和挥动日志。
- 主界面的“校准手持零点”：自然握持后点击，以当前融合姿态作为零点；
  不要求完全静止，也不把手部运动写成陀螺仪偏置。有稳定窗口时可同时校正重力方向。
  校准后的屏幕基点会立即回到并保存为 Codex 窗口中心。它是相对姿态校准，
  不是绝对空间定位，也不能提供无漂移的绝对航向。完成方向向导后使用学习的
  安装关系与左右正负号；未学习时才回退到 PCB 轴。实际安装后的方向仍需手持检查。
- 右上角齿轮设置页：引导采集 15 次完整挥鞭轨迹和 5 次放桌反例，
  自动选出代表模板，并可调整 V3 匹配容差；14 项板端参数仍可编辑。
  配置保存在 `%LOCALAPPDATA%\CodexWhip\detector-profile.json`，每次 BLE 重连
  自动下发到开发板。
- 消息设置：文案以卡片编辑，可拖动排序，并可切换“顺序发送”或
  “随机发送”。保存后无需重启，下一次挥鞭直接生效；配置位于
  `%LOCALAPPDATA%\CodexWhip\message-profile.json`。
- 视觉效果设置：可把 PCB 伤口设为每 `1–100` 次抽打出现一次；设置为 `N` 时，
  第 `N、2N、3N…` 次有效命中生成伤口，默认值 `1` 保持每次都出现。没有生成
  新伤口的命中仍会延后已有伤口愈合。保存后立即生效并重新计数，配置位于
  `%LOCALAPPDATA%\CodexWhip\visual-settings.json`。
- 桌面视听反馈：程序找到唯一的 Codex 窗口后，会在窗口中心（或已保存的位置）显示通体近黑色、
  细棍手柄的卡通鞭子；鞭绳相对 1.1.0 加长 `50%`，重力提高 `20%`，并通过
  `0.80` 惯性保留系数与 `0.065 px/物理帧` 速度休眠抑制静止乱飘。桌面 `1.3.6` 还让
  鞭绳无速度注入地跟随手柄 `40%` 位移，减少绳索相对手柄积累的惯性和长时间甩动。实体手柄停止后锚点
  保持稳定，但鞭绳仍继续经过重力、约束和阻尼自然收敛，不会当帧冻结。
  桌面 `1.3.7` 建立了传感器全量程映射；桌面 `2.0.1` 将最终活动范围收紧为窗口正中央的
  `1/3 宽 × 1/3 高` 区域。自动抽打使用当前手柄、绳形和角度生成落点，越界鞭梢会回收到窗口内，
  屏幕实际鞭梢位置与伤口坐标使用同一个点。PCB 伤口已移除外围黑色阴影及浅色碎纸纤维。
  桌面 `1.3.8` 在最终屏幕映射层反转传感器 Y 轴，使实体手柄上下运动与屏幕一致；
  桌面 `1.3.9` 将每次伤口的长轴改为跟随实体手柄最近一轮运动轨迹的主轴，
  不再使用固定的屏幕抽打动画定向；轨迹累计会降低末段制动和回弹对角度的干扰，
  相近伤口仍按原逻辑合并。
  Codex 打开、关闭、最小化或恢复时，
  鞭子会自动同步显示或隐藏。
  有效挥动会播放 280 ms 大幅抽打动画和
  “真实破空鞭响＋落点闷震”分层音效，并让非最大化的
  Codex 窗口进行 220 ms 强化抖动，随后精确回到原位置。
- 六轴数据经四元数姿态融合后驱动相对指向，水平 `±25°`、垂直 `±20°` 对应
  内部 `±190 × ±130` 控制域，再映射到窗口中央三分之一区域；扭转最多 `±42°`。
  角速度采用三样本中值滤波及 `0.25 dps` 死区，微小转腕不再被旧版 `12 dps` 门槛吞掉。
  加速度仅在可信条件下校正重力方向，不产生平移；握住某个角度时短暂保持屏幕位置，
  以宽松标准连续静止三秒后自动归中。数据流消失三秒的视觉回中兜底仍保留。
  250 ms–3 秒的短缺口保持已有姿态、跳过缺失积分，
  不突然回到中心；超过三秒或设备重启则重建基准。桌面手持归中不学习运动零偏；
  固件上电时的零偏校准仍需保持手柄静止约 1–3 秒。
  传感器手柄锚点不受绳索惯性反推；手柄停下后，绳索仍单独经过物理步进衰减。
  自动抽打会从当前物理姿态开始，并以当前手柄锚点和方向生成动态鞭梢命中点；
  鼠标抽打仍精确命中点击坐标。传感器没有绝对位置或航向基准，因此这不是
  空间坐标追踪，不能保证现实握柄与
  屏幕位置一一对应。
- 鼠标或实体芯片移动时，卡通鞭子采用受 VibeWhip/badclaude 启发的分段
  Verlet 物理：渐细绳体、长度约束、手柄端高刚度、鞭梢低刚度、弯曲限制与
  Catmull-Rom 平滑。命中时从固定覆盖整个 Codex 窗口的同一张写实 PCB 底图
  显型；相近命中的破口遮罩会先融合，遮罩外保持完全透明，
  因此连续抽打会扩大同一处伤口而不会叠加白边。任意一次新抽打都会重置全局
  静止计时：停止抽打满 3 秒后才开始愈合，再用 `0.85 秒` 完成闭合。
- Codex 适配器：只接受 Windows 商店包路径含 `OpenAI.Codex_` 的可见
  `ChatGPT.exe`，目标不唯一、输入框已有草稿或输入框识别不清时拒绝发送。
- 图形界面默认安全监听，只有手动勾选“允许挥动后实际发送”才会武装。

Windows 1.5.4 的完整源码、用户配置、学习轨迹和语音模型已单独备份。
Mac 移植使用相同的检测、鞭绳物理、音效、伤口、消息和语音逻辑，平台层改为

## 1. 准备桌面端

在 PowerShell 中进入本目录：

```powershell
.\scripts\setup-desktop.ps1
.\scripts\test.ps1
```

先运行一次纯模拟，它不会碰 Codex：

```powershell
.\.venv\Scripts\codex-whip.exe simulate
```

检查电脑能否唯一识别 Codex 窗口：

```powershell
.\.venv\Scripts\codex-whip.exe doctor
```

启动图形界面：

```powershell
.\.venv\Scripts\codex-whip-gui.exe
```

也可以构建无需 Python 环境、可直接双击的单文件 Windows 程序：

```powershell
.\scripts\build-desktop.ps1
```

产物为 `dist\CodexWhip.exe`。程序启动后会自动扫描 `CodexWhip`，但保持
“安全监听”。确认蓝牙和 Codex 都就绪后，手动勾选“允许挥动后实际发送”。
鞭子和窗口抖动不依赖“实际发送”开关，在安全监听模式下也可以用
“模拟挥动”验证，不会向 Codex 输入文字。

### 学习校准与阈值设置

1. 点击主窗口右上角齿轮，选择“开始采集 15 次挥鞭”。每次自然挥动一次后，
   立即点击“录入刚刚动作”。V3 直接从最近 1.8 秒原始数据中截取最强的
   720 ms 轨迹，不需要先被旧阈值判定成功。
2. 正样本完成后，推荐选择“采集 5 次放桌动作”，按平常方式拿起、放下鞭子。
   这一步用于排除“放到桌上反而触发”的已知反例，也可以明确跳过。
3. V3 模型完成后会自动保存到 `%LOCALAPPDATA%\CodexWhip\motion-profile-v3.json`，
   并立即接管识别。“V3 匹配容差”越高越容易触发；调整后需用实物复测。

“平均值”只用于展示典型动作，不直接作为唯一门槛：仅用正样本均值无法判断
放桌动作与挥鞭的差异。实际建议值保留至少 80% 的正样本回放，并优先压低已采集
反例的误通过数。

语音双敲学习也使用手动录入：在“语音输入”中点击“开始重新学习”，自然双敲
桌面一次，再立即点击“录入刚才双敲”。软件直接分析最近约 2.2 秒六轴原始数据，
不要求旧双敲阈值先识别成功；只有点击并找到两次分开的冲击后才计数，共录入 5 次。
这 5 次完整轨迹会保存为 `%LOCALAPPDATA%\CodexWhip\double-tap-profile-v2.json`。
运行时先用宽松双峰范围寻找候选，再使用与挥鞭 V3 相同的角速度、动态加速度、
加速度变化率特征和 DTW 模板距离确认；设置页峰值不再独自决定是否触发录音。
识别出文字但不想发送时，直接再次双敲：开发板确认新录音开始后，旧文字立即清空；
新录音没有检测到人声时保持空白，不会沿用旧文字。

## 3. 分阶段验收

第一阶段只观察事件和文案，不向 Codex 发送：

```powershell
.\.venv\Scripts\codex-whip.exe run
```

确认普通拿起、走动不触发，明确挥动能稳定输出 `WHIP2` 后，再开启真实发送：

```powershell
Copy-Item .\desktop\config.example.toml .\config.toml
.\.venv\Scripts\codex-whip.exe --config .\config.toml run --live
```

真实发送会把 Codex 窗口带到前台。若当前输入框已有未发送文字，程序默认拒绝
操作，防止覆盖草稿。UI自动化仍可能受 Codex 版本变化影响，因此每次更新
Codex 后应先重新运行 `doctor` 和 `simulate`。

### 自定义文案

优先使用主窗口右上角齿轮中的“发送消息”：可直接编辑、添加、删除、拖动
排序并设置顺序/随机。`config.toml` 中的 `[messages].items` 仍作为首次启动默认值。

## BLE 文本协议

开发板以换行结尾发送：

```text
WHIP2,<sequence>,<peak_gyro_dps>,<peak_accel_g>,<duration_ms>,<angular_travel_deg>,<direction_consistency>,<dominant_axis_ratio>,<peak_gap_ms>,<peak_jerk_gps>
RAW5,<sequence>,<start_timestamp_ms>,<base64 timed int16 six-axis samples>
```

RAW5 每帧为小端 `<Hhhhhhh>`：相对首帧时间（ms）、三轴角速度（0.1 dps/LSB）、
三轴加速度（0.001 g/LSB）；每包最多四帧。电脑端仍兼容 RAW3/RAW4 和 V1 的五字段 `WHIP` 消息。
`direction_consistency` 和
`dominant_axis_ratio` 的范围是 `0..1`，越接近 1 代表动作越接近单向、单轴挥动。

可从 BLE UART RX 向开发板发送：`PING`、`STATUS`、`SELFTEST`、`ARM,1`、`ARM,0`、
`CAL`、`TEST`、`TEST,SLOW`、`TEST,REBOUND`、`RAW,0`、`RAW,1`、`RAW,2`、`LEARN,START`、
`LEARN,TAKE`、`LEARN,STOP`、`CFG,GET`、`CFG,RESET` 和 `CFG,<键>,<值>`。
`LEARN,TAKE` 只提交开发板暂存的最近动作；若没有完整动作则返回 `LEARN,EMPTY`。
`SELFTEST` 对默认和当前配置分别运行六种合成轨迹，只返回结果，不发送 WHIP、
不更改用户配置或启动录音。验收命令：
`.\.venv\Scripts\python.exe scripts\verify-motion-v21.py --report outputs\motion-v2.1.0\device-verification.json`。
运行前关闭其他鞭子程序，保持开发板静止。其他 `TEST` 命令会把合成轨迹
实际送入 V2 检测器；`TEST,SLOW` 验证约 850 ms 的较慢挥动，
`TEST,REBOUND` 验证带明显制动回弹、净方向接近零的挥动。

学习模式会为每个宽松捕获到的动作发送：

```text
SAMPLE3,<序号>,<结果>,<峰值角速度>,<峰值动态加速度>,<时长>,<角位移>,<方向一致性>,<主轴集中度>,<峰值差>,<冲击变化>
```

固件 `0.2.2` 起，被候选检测器拒绝的动作会发送 `REJECT2` 诊断行，包含拒绝
原因、峰值、角位移、方向一致性、主轴集中度及峰值时间差；它只用于校准，
不会触发电脑端文案或 Codex 发送。
